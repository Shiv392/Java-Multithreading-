⭐⭐⭐ Problem Statement ======================>
Abhi tak tum thread aise bana rahe the.

Thread t1 = new Thread(new Counter());
Thread t2 = new Thread(new Counter());

t1.start();
t2.start();
Suppose tumhe

10 Threads banane hain.
Theek hai.

Ab socho

1000 Client Requests har second aa rahi hain. Har request ke liye
new Thread(...)
karoge.

Thread t1 = new Thread(task1);
Thread t1 = new Thread(task2);
Thread t1 = new Thread(task3);
...
Thread t1000 = new Thread(task1000);
Question:
Kya problem hogi?

Problem 1 — Thread Creation Cost
Thread banana free nahi hota.
OS ko
Memory allocate karni padti hai.
Stack create karna padta hai.
Scheduler me register karna padta hai.
Ye expensive operation hai.

Problem 2 — Context Switching
1000 threads
↓
CPU sirf 8 cores.
Ab CPU continuously switch karega.
Thread1
↓
Thread55
↓
Thread890
↓
Thread3
↓
Thread700

Ye context switching bahut costly hai.

Problem 3 — Memory
Har thread apna stack rakhta hai.
Example:
Agar ek thread ~1 MB stack use kare.
1000 threads ≈ 1 GB sirf thread stacks.
Ab application ka memory usage bahut badh gaya.

Problem 4 — Thread Lifetime
Suppose Thread sirf 100 ms ka kaam karta hai.
Fir terminate.
Next request
↓
Fir
new Thread(...)
Fir create.
Fir destroy.
Ye creation-destruction baar-baar ho raha hai.
Waste.

Real World Example
Amazon server
Suppose
10,000 Requests / second
Agar har request ke liye
new Thread()
banaya jaye,
Server crash hone ke chances badh jayenge.

This problems solves by Executor Services
